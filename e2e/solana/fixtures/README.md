# Solana test fixtures

This directory holds the Solana **mainnet** state that the end-to-end tests load into a local
[`solana-test-validator`](https://docs.anza.xyz/cli/examples/test-validator), so the tests exercise
pump.fun's real on-chain programs instead of mocks. Nothing here is a Splitdev artifact: it is all
dumped, unmodified, from mainnet and used only for local testing.

## Contents

- `programs/` — program binaries (BPF `.so`, some stored gzipped as `.so.gz`) dumped from mainnet with
  `solana program dump`. These are pump.fun's programs (pump, pump AMM, pump fees) and the SPL token
  programs they depend on.
- `accounts/` — account snapshots in `solana-test-validator --account` JSON format: the existing mainnet
  accounts that the launch, trade and fee-sharing instructions touch (pump.fun's globals and fee configs,
  mints, sysvars, and so on).
- `programs.txt` — the list of program ids that are dumped into `programs/`.

## Provenance and regeneration

These files are a point-in-time copy of mainnet. They are regenerated by the **Solana fixtures** workflow
([`.github/workflows/solana-fixtures.yml`](../../../.github/workflows/solana-fixtures.yml)), which is run on
demand via `workflow_dispatch`. The workflow runs `e2e/solana/collect-fixtures.mjs` to collect the accounts
and `programs.txt`, then `solana program dump -um` for each program id in `programs.txt`.

The workflow writes plain `.so` files. Three of the program binaries are committed gzipped (`.so.gz`)
because the dumps keep the zero padding of their mainnet accounts (up to 10 MB each).
[`validator.sh`](../validator.sh) loads either form, so after a refresh you can re-compress them with
`gzip -9` or commit them as dumped.

Do not edit these files by hand; re-run the workflow to refresh them when pump.fun's programs change. See
the repository [README](../../../README.md) for how the integration tests use these fixtures.
